AgentBoard: An Analytical Evaluation Board of Multi-turn LLM Agents

AgentBoard：多轮 LLM 智能体的分析式评测板

Chang Ma、Junlei Zhang、Zhihao Zhu、Cheng Yang、Yujiu Yang、Yaohui Jin、Zhenzhong Lan、Lingpeng Kong、Junxian He，香港大学、浙江大学、上海交通大学、清华大学、西湖大学、香港科技大学

NeurIPS 2024 数据集与基准赛道
深度学习自然语言处理大模型评测智能体基准
背景

领域定位

深度学习，自然语言处理
大语言模型的能力评测：MMLU、GSM8K、HumanEval
把大模型当智能体来评测：AgentBench、GAIA、MINT
多轮交互、部分可观测、按步计分：AgentBoard

MMLU、GSM8K 这类基准一次给出完整题目，模型一次作答，测的是知识和单步推理。智能体评测关心的是另一种能力：在一个会对动作作出反应的环境里连续做几十个决定，边做边收集信息，记住已经知道的事，发现走错后改正。这种能力只有在多轮交互中才会暴露出来，单轮问答测不到。

AgentBoard 的贡献在测量方法上，它没有训练新模型。它提供一个基准（4 类场景、9 种任务、1013 个测试样本[[envs]]），一个在每一步都给分的进度指标，以及一套把运行记录拆开分析的开源工具。

背景

基本概念

LLM 智能体
大模型读入环境的文字描述，输出一个文字动作（例如 open fridge 1），环境执行后用文字返回结果，循环往复直到完成任务或用完步数。
多轮交互
一个样本需要多次“观察、行动”的往返。每一步的决定会改变后续能看到的信息，早期的错误会累积。
部分可观测
智能体一开始看不到全部状态，比如不知道哪个柜子里有鸡蛋，必须主动去看[[po]]。这迫使它探索并记住探索结果。
POMDP
部分可观测马尔可夫决策过程，是上面这种交互的数学写法[[pomdp]]：给定目标 g，智能体根据目标和历史观察选动作，环境转移到新状态并返回新的观察。读懂后文不需要它的公式。
成功率
在限定步数内完整达成目标的样本比例，每个样本只有 0 和 1 两种结果。
进度率
本文提出的指标，每一步给出 0 到 1 之间的分数，表示到这一步为止离目标有多近。
Grounding
把想法落实成环境能执行的动作。grounding 准确率是模型输出的动作中合法动作所占的比例[[grounding-def]]，反映模型是否守格式、是否用对动作名。
Act 与 ReAct
两种提示方式。Act 只让模型输出动作；ReAct 让模型先写一段推理再输出动作，推理文字会进入后续的上下文。
主线

问题、方案、验证、发现

问题

现有基准要么任务种类单一，要么大部分是单轮题，要么信息一开始就全给了[[obstacle]]。而且几乎都只报最终成功率[[sr-only]]，在难任务上大家都接近 0，比不出高下[[zero-sr]]。

方案

挑选并改造 9 种需要多轮、大多部分可观测的纯文本任务；给每个样本标注子目标或匹配规则；每一步计算进度率，取历史最高值[[pr-def]]。

验证

8 种任务各 60 条运行记录，由 4 人在不看自动分数的情况下打分。进度率和人工分的相关系数在所有任务上都超过 0.95[[human]]。

发现

GPT-4 平均进度率 70.0%，大幅领先[[gpt4]]。能否持续多轮推进是强弱分水岭[[finding-multiturn]]，而这依赖 grounding、世界知识和自我纠错等基础能力[[finding-basic]]。

是的，九个“环境”就是 AgentBoard 的九种任务。容易混淆的原因是论文把 environment 用在了两个层级上：“nine diverse environments across four scenarios”指九种任务[[nine-env]]，“1013 exemplary environments”和 Table 14 的 “# Environment” 指具体样本[[envs]]。本页统一把前者称为任务，后者称为样本。一种任务规定世界的规则和可用的动作，一个样本再指定具体目标和初始状态，比如 AlfWorld 这种任务下的一个样本是“把洗干净的鸡蛋放进微波炉”。评测一个模型时，它要逐个跑完这 1013 个样本，每种任务得到一个分数，九种任务再求平均。

样本数
这种任务下有多少个不同的目标和初始状态，原表的 # Environment。
# Turns
原表注没有定义。它不是步数上限，因为实验最多允许 30 轮交互[[turns-30]]。从取值看，它更接近完成一个样本通常需要的轮数，这是本页的推断。
动作种类
原表的 Action Space，动作模板的数量。WebShop 只有 search 和 click 两种，Jericho 有 150 种。
平均子目标
一个样本平均要完成几个里程碑。没有子目标的任务，这里是目标状态要满足的条件数。
难题门槛
子目标数超过这个值的样本算难题[[hard-cutoff]]，后面“易题与难题”的分组由它决定。
上下文 token
提示的长度，用 Llama2 分词器统计。WebArena 的网页结构很长，约 15000 token，对上下文较短的模型压力最大。
进度算法
subgoal 数已完成的子目标，match 比较当前状态和目标状态的相似度，下一个面板解释两者的区别。

九种任务大多来自已有研究，改造围绕三件事：统一成纯文字的输入输出，让所有文本模型都能参评，比如 BabyAI 原本是图像观察和数字动作；补齐或重标子目标，比如 ScienceWorld 原有子目标稀疏且权重不均；改进报错信息，让模型犯错后有机会纠正，比如 WebShop 越界和点错对象时的反馈。另有两处修补具体漏洞。Jericho 原游戏要 50 到 300 步，超出模型的上下文能力，于是改写目标，限制在 15 个子目标内[[jericho]]。Tool-Query 的问题刻意设计成凭记忆答不出来，即使答案碰巧正确，没有查库也判错[[tq]]。

竖着看，前三列每个已有基准都至少缺一项；后两列所有已有基准都打叉，这两项是 AgentBoard 新加的。缺口的后果可以从相关性上看出来：AgentBench 的分数和知识测验 MMLU 高度相关，AgentBoard 的分数则和推理、代码基准相关[[vs-agentbench]]。前者很大程度上在测模型知道多少，后者在测模型能否一步步把事做成。

只看成功率还有一个问题：它把“走完四步中的三步”和“一步没走”都记为失败[[near-complete]]。对弱模型来说，几乎所有样本都失败，成功率只剩下噪声；对研究者来说，看不到模型是卡在第一步还是倒在最后一步，也就无从改进。这正是后两列要解决的问题。

方法

所有模型用相同的智能体写法

Figure 2

评测要比较的是模型，如果给不同模型配上复杂程度不同的规划、反思或记忆模块，分数差异就分不清来自模型还是来自框架。所以全部采用图左的简单结构：模型拿到目标、当前观察和之前的全部观察与动作，生成下一个动作；提示词如图右，只要求输出动作（Act[[act-only]]），外加一个示范例子。历史超过上下文长度时只保留最近若干轮[[sliding]]，交互得以进行到步数上限，上下文较短的模型不会因提前终止而被额外扣分。

方法

进度率怎么算

§2.2

进度率要解决的问题是：样本没做完时，怎样给出一个能比较的部分分。不同任务的状态形式不同，所以有两种算法，二者都输出 0 到 1 的分数，最后都取历史最大值。

subgoal：数里程碑（AlfWorld 等）

中间状态难以直接和目标比较的任务用这种算法。人工把目标拆成 K 个有先后顺序的子目标，每个子目标对应环境文字里的一段可检查内容，用正则表达式判断是否达成[[regex]]。分数等于已达成子目标的比例。

rt = max0≤i≤t ( 1/K × Σk f(si, gk) )，f ∈ {0, 1}

match：比较当前状态和目标状态（PDDL 等）

状态可以逐项比较的任务用这种算法。比如目标是“a 在 b 上，b 在桌上”，当前是“a 在桌上，b 在桌上”，两个条件满足一个，匹配分 0.5[[pddl-match]]。表格操作按单元格比较，网页任务按网址和页面内容比较。

rt = max0≤i≤t f(si, g)，f ∈ [0, 1]

做到这一步时的进度率0.250.500.751.00
做到这一步时的成功率0001

上表就是这个指标相对成功率多出来的信息。取最大值的用意在于容忍探索：智能体经常要走回头路，比如为了找东西离开厨房，这时当前状态和目标的距离会暂时变远，直接用当前状态打分会惩罚探索。取最大值记录的是“最远推进到了哪里”。代价是分数不会下降，智能体后来破坏了已完成的部分也看不出来。

为了让子目标标得出来，每个目标只允许对应一种子目标顺序，约 5% 的原题因此被改写。这个约束只限制里程碑的顺序，绕路完成同样能拿满分[[detour]]。它也意味着进度率最适合目标明确、路径相对固定的任务。页面末尾的附录用一个完整样本演示了这个计算过程。

验证实验：进度率可信吗

进度率是人为定义的分数，只有它和人对“做到哪了”的判断一致，才能拿它比较模型。后面所有结果都以此为前提。

验证

进度率与人工判断是否一致

Figure 3§3.2

做法是请 4 位标注者阅读运行记录和任务描述，在看不到自动分数的情况下给出进度（0%、25%、50%、75%、100% 五档），再和进度率比较。每种任务取 60 条记录，来自 GPT-4、GPT-3.5-Turbo、DeepSeek-67b 三个模型。

图中每个点是一条记录，横轴是 4 人打分的平均，纵轴是进度率。结果是相关系数 ρ 在所有任务上都不低于 0.95，点基本贴着对角线。κ 衡量 4 位标注者彼此的一致程度，在 0.73 到 0.91 之间，说明人工分本身是稳定的参照。结论是进度率可以代表人对进度的判断。

用智能体运行记录微调的收益最大：AgentLM-70b 比基座进度率高 9.5、成功率高 10.2 个百分点。它的训练数据只来自 AlfWorld 和 WebShop，在其他七种任务上也有明显提升[[agentlm]]，学到的是一般的交互习惯，而非两种任务的特定解法。

这组实验检验“统一用 Act”是否吃亏。结果是先写推理再行动的 ReAct 没有稳定地胜过只输出动作的 Act[[react]]：工具任务上略好，AlfWorld 的成功率和 PDDL 反而下降。一种解释是交互最长 30 轮，推理文字会更快填满上下文，挤掉更早的观察。长历史的处理方式也做了对比，只保留最近记录好于“上下文满了就停止”，也比“让模型总结历史”更稳定。

结论

结论

GPT-4 在所有任务和所有子能力上都领先，开放模型中 Llama3 和 DeepSeek LLM 最好。强弱智能体的分界线在于能否在多轮交互中持续推进，大多数开放模型在几步之后就停滞[[finding-multiturn]]。持续推进的能力建立在 grounding、世界知识和根据反馈自我纠正等基础能力之上[[finding-basic]]。代码数据和智能体交互数据都能在不增加参数的情况下明显改善这些能力。

方法上，进度率让评测在成功率接近零的区间仍然有分辨率，难易分组、按步曲线和子能力拆解把一个总分变成了可以定位问题的诊断信息。具体名次会随新模型过时，这套测法的价值更持久。

局限

局限与讨论

进度率依赖人工标注的子目标[[limit]]。任务越复杂，标注的人力成本越高；用大模型自动标注是自然的方向，但当时的模型在这些任务上表现不佳，标注不可靠。评测全部在模拟环境中进行，是为了保证结果可复现；真实网站内容随时变化，在真实环境中操作也有安全风险，这两点都还没有解决。

统一的 Act 写法让比较公平，但分数反映的是模型自身的能力，不代表配上更好的规划、记忆或反思模块后能达到的水平，排行榜应理解为基础能力排名。
